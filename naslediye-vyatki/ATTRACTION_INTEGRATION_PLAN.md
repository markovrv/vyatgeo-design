# План интеграции модуля «Архитектура и скульптура г. Кирова» (attraction)

Раздел: `src/views/ArchitectureView.vue` + `src/views/ArchitectureObjectView.vue`.
Источник данных: плагин `api/attraction` (CPT `attraction`), REST на `https://testsite.vyatgeo.ru/wp-json/`.
Карта — на основе прежнего прототипа `C:\Users\Роман\Desktop\Проекты\wp\attraction\vue\attraction-map`.

## 1. Что изучено

- Код плагина `api/attraction` (`rest-api.php`, `register-attraction.php`, `activation.php`).
- Живой сервер: `GET /wp-json/attraction/v1/objects` — 423 объекта, координаты заполнены у всех (0 пустых), `summarize`/`content` намеренно пустые в этом bulk-ответе (см. `api/docs/attraction.md`).
- Старый прототип карты — самостоятельный Vue 3 + Vite проект (`vue-yandex-maps` + `vuestic-ui`), собранный отдельно от текущего `naslediye-vyatki` и когда-то встроенный в WP-страницу `attraction-map` как готовый бандл.
- Текущий Vue-стаб (`ArchitectureView.vue`/`ArchitectureObjectView.vue`) — полностью статичная демо-заглушка: 10 придуманных зданий, SVG-карта с координатами «на глаз», фильтры «По стилю»/«Сохранность», которых нет в реальных данных.

## 2. Текущее состояние API

- **CPT `attraction`**, таксономий нет (`'taxonomies' => []`) — в отличие от Этнографии, категорийного фильтра в данных не существует вообще.
- **Мета-поля** (плоские, без денормализации терминов): `attraction_coord` (`"lat, lng"`), `attraction_place`, `attraction_imgSrc`, `attraction_color` (HEX, у каждого объекта фактически **свой уникальный** цвет — проверил на живых данных: 423 объекта, ~420 разных цветов, то есть цвет не кодирует категорию, это просто цвет маркера конкретного объекта), `attraction_summarize`.
- **Единственный кастомный endpoint**: `GET attraction/v1/objects` — всё сразу, без пагинации, без поиска, без фильтров. `summarize`/`content` в нём всегда пустые (осознанно, см. `api/docs/attraction.md`) — для деталей нужен отдельный `GET /wp/v2/attraction/{id}` (там `attraction_summarize` и `content.rendered` отдаются корректно через `register_rest_field`).
- Страницы `attraction-about` и `attraction-map` существуют на сервере как стандартные WP `pages` с реальным текстом — можно забирать через `GET /wp/v2/pages?slug=attraction-about` для блока «О разделе», не выдумывая текст заново.

## 3. Что было в старом прототипе карты (для переиспользования)

Стек: `vue-yandex-maps` (Vue3-нативная библиотека, MIT) + `vuestic-ui` (модалки/карусель/тосты) + `axios`.

Функционал:
- Кластеризация точек (`yandex-map-clusterer`) с кастомной иконкой кластера — круговая диаграмма-«пирог» (`CircularChart.vue`, `<canvas>`), показывающая соотношение цветов объектов внутри кластера.
- Кастомный пин — круглое фото объекта (`imgSrc`) на цветной SVG-подложке (`marker.vue`), с фолбэком на дефолтную картинку (`green-capybara.png`), если `imgSrc` пуст.
- Инфобокс при наведении (`markerInfo.vue`) — заголовок + место, появляется только при достаточном зуме.
- Клик по пину → модалка (`VaModal`) с полным описанием, каруселью доп. фото (`VaCarousel`, изображения парсились прямо из HTML `content.rendered` по тегам `<img>`) и кнопкой перехода на исходную WP-страницу объекта.
- Хеш-роутинг для диплинков на конкретный объект (`#point/123`) и на страницу «О разделе» (`#page/info`).
- Historical polygons — 4 GeoJSON-файла (границы Хлынова/Вятки в XVII, XVIII, 1812 гг. и территория кремля), отрисованные поверх карты слоями.
- День/ночь переключатель темы карты (сохраняется в `localStorage`, требует полной перезагрузки страницы).
- **AI-пересказ через ChatGPT** — по клику генерировался краткий пересказ описания объекта через внешний прокси (`credentials.php`, отдельный API-ключ), результат сохранялся обратно в `attraction_summarize`. Полностью опционален (`CONFIG.gptOn`), требует чужой платный бэкенд-прокси и учётные данные, которых у нас сейчас нет.

## 4. Расхождения и решения, нужные от вас

### 4.1 Нет категорийного фильтра в данных
Текущий стаб придумывает «Стиль» (классицизм/модерн/конструктивизм/…) и «Сохранность» (сохранился/утрачен) — в реальных данных `attraction` таких таксономий нет вообще (только уникальный цвет на объект, ничего не группирующий). Варианты:
- **(a) Убрать эти фильтры**, оставить только карту + список + поиск по названию/описанию — рекомендую для первого этапа, без доп. работы на бэкенде.
- (b) Завести таксономии `attraction_style` и `attraction_status` на бэкенде и разметить 423 объекта (вручную или гибридным rule+LLM способом, как это было сделано для `finding_type` в Этнографии) — отдельный, сопоставимый по объёму проект.

### 4.2 Нужен API-ключ Яндекс.Карт
`vue-yandex-maps` требует ключ JS API (`window.map.mapKey` в старом прототипе — жёстко не был зашит, вводился отдельно при каждом развёртывании). В проекте `geopoints` в админке уже используется один ключ (`ba0d0589-f903-43e9-b3d3-cc290988b69a`), но это старый JS API 2.1 и вопрос, привязан ли он к домену `heritage.vyatgeo.ru` (Яндекс обычно привязывает ключ к конкретным доменам). Нужно either переиспользовать существующий ключ (если домен разрешён), либо завести новый в кабинете Яндекса именно под этот проект.

### 4.3 AI-пересказ (ChatGPT) — переносить или нет
Требует отдельного backend-прокси с API-ключом OpenAI/совместимого сервиса, которого у нас нет и который стоит денег за каждый вызов. Предлагаю **не переносить** — просто показывать то, что уже есть в `attraction_summarize` (заполняется вручную в wp-admin), без автогенерации. Если понадобится позже — отдельная задача.

### 4.4 Исторические полигоны границ города — переносить ли
Уникальная и содержательная фишка (наглядно показывает, как рос город), но требует переноса 4 GeoJSON-файлов в новый проект и решения, показывать ли их по умолчанию или по переключателю. Предлагаю перенести — это чистые статичные данные, без зависимости от AI/внешних сервисов, добавляет метапу ценность разделу об архитектуре.

### 4.5 Идентификатор объекта в URL
Как и в Этнографии — `/architecture/:id` (числовой), а не `:slug` — `attraction/v1/objects` не отдаёт `post_name`, а числовой ID уже есть и всегда уникален.

## 5. Архитектурные решения

### 5.1 Карта — реальная библиотека вместо SVG-заглушки
Заменить самодельный `CatalogMap.vue` (условный SVG-прямоугольник с точками) на `vue-yandex-maps`, перенеся из старого прототипа: кластеризацию, кастомные пины (фото+цвет), hover-инфобокс, историч. полигоны (см. 4.4). **Без** AI-пересказа, **без** дневного/ночного переключателя (не критично для первой версии, можно добавить позже), **без** хеш-роутинга модалок — вместо модалки клик по пину ведёт на обычную страницу `/architecture/{id}`, как во всех остальных 6 модулях сайта (единообразие вместо смеси SPA-модалок и роутов).

### 5.2 Данные — один запрос на весь модуль, не постраничный API
В отличие от Этнографии (767 находок с тяжёлыми фото/текстом на каждую → серверная пагинация была нужна), здесь 423 объекта и **карта в любом случае требует весь датасет в памяти клиента одновременно** (кластеризация не работает постранично). Поэтому: `useAttractions()` — один запрос ко всей коллекции (как сейчас и делает `attraction/v1/objects`), фильтрация/поиск/пагинация каталожного вида — **на клиенте** поверх уже загруженного массива, без изменений бэкенда. Это проще, чем городить серверную пагинацию только ради каталожного режима просмотра.

### 5.3 Деталь объекта
`useAttraction(id)` — `GET /wp/v2/attraction/{id}`, забирает `attraction_summarize` + `content.rendered` + остальные мета-поля по требованию, по аналогии с тем, как `EthnographyItemView` подтягивает недостающие поля отдельным запросом.

## 6. Каталог — что берём из наработок Этнографии

- `CatalogLayout.vue`, `Pagination.vue` (клиентская пагинация вместо серверной — компонент тот же, просто `total`/`totalPages` считаются на фронте от полного массива).
- Поле поиска по названию/описанию — debounce 400мс, как в Этнографии, фильтрация на клиенте (`title`/`place`/`summarize`, если доступен).
- Переключатель «Карта / Список» — уже заложен в текущем стабе (`viewOptions`), оставляем эту идею, но без фильтров стиля/сохранности (см. 4.1), пока не будет принято решение.
- Общее состояние (аналог `ethnographyCatalogState`) — фильтр/страница/прокрутка переживают переход на страницу объекта и обратно.

5. Переписать `ArchitectureView.vue`: реальные данные вместо статичных 10 зданий, карта на новой библиотеке, список с клиентским поиском/пагинацией, убрать несуществующие фильтры (или добавить, если решите делать таксономии).
6. Переписать `ArchitectureObjectView.vue`: параметризовать по `:id`, подтягивать `attraction_summarize`/`content` отдельным запросом, синхронизировать состав полей с тем, что реально есть в данных (адрес/место, описание, фото).
7. Обновить `router/index.js`: `:slug` → `:id` для `architecture-object`.
8. QA: сверить, что все 423 точки корректно кластеризуются и открываются, карта не тормозит на полном датасете, детальная страница показывает `attraction_summarize`.

## 8. Вне охвата этого этапа

- AI-пересказ через ChatGPT (см. 4.3) — не переносим без отдельного решения по бюджету/бэкенду.
- Таксономии стиля/сохранности (см. 4.1) — только если явно решите делать, это отдельный подпроект по объёму как разметка `finding_type`.
- День/ночь переключатель темы карты — опциональное улучшение, не первой необходимости.
