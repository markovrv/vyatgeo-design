# Проект «Наследие Вятки» (Vue-версия)

Историко-культурное наследие Кировской области — сайт к 90-летию региона (1936–2026). Эта директория (`naslediye-vyatki/`) — рабочая Vue 3 + Vite реализация; статический HTML-прототип в корне репозитория (`../index.html`, `../*.html`, `project/*.dc.html`) сохранён только для референса дизайна и не разрабатывается дальше.

## Структура

```
src/
  main.js                # tokens.css → base.css → Vue app + router + vue-yandex-maps
  router/index.js        # lazy-loaded маршруты
  config/
    api.js                # API_BASE_URL из window.__API_BASE_URL__ (index.html)
    maps.js               # YANDEX_MAPS_API_KEY из window.__YANDEX_MAPS_API_KEY__
    attraction.js         # ATTRACTION_NEARBY_RADIUS_KM из window.__ATTRACTION_NEARBY_RADIUS_KM__
  composables/
    useAttractions.js     # модуль «Архитектура» — реальный WP REST API
    useFindings.js        # модуль «Этнография» — реальный WP REST API
  components/             # общие: CatalogLayout, FilterBar, Pagination, ImageLightbox,
                           # AttractionMap/Controls/Gallery/Popup, MultiSelectFilter, TypeFilterTiles…
  views/                  # по одной паре {Module}View.vue + {Module}ItemView.vue на раздел
styles/
  tokens.css              # дизайн-токены (:root)
  base.css                # reset, focus-visible, prefers-reduced-motion
api/                      # исходники бэкенд-плагинов WP (рабочая копия для этого же сервера,
                           # правки здесь реально применяются на testsite.vyatgeo.ru)
  attraction/rest-api.php
  artifact-finder/rest-api.php
  docs/*.md               # описание REST-эндпоинтов каждого плагина
```

На сегодня с реальным API интегрированы 2 из 7 модулей — **Архитектура** (`attraction`) и **Этнография** (`artifact-finder`/findings). Остальные (VictoryFaces, HistoricCities, Nature, Archeology) — на статичных моковых данных, интеграция не начата.

## Паттерны модулей с реальным API

Ниже — то, что уже устоялось в двух интегрированных модулях (Архитектура, Этнография) и стоит повторять один в один при подключении следующего модуля к реальному API, а не изобретать заново.

### Composables (`src/composables/use*.js`)

- Список: `useXxxs()` → `{ items, loading, error, fetchXxxs }`. Один объект: `useXxx()` → `{ item, loading, error, fetchXxx(id) }`. Никогда не бросают наружу исключения — ошибка складывается в `error.value`, компонент сам решает, что показать.
- Состояние каталога — реактивный **module-level singleton** (`export const xxxCatalogState = reactive({...})`), а не `ref` внутри компонента: так фильтр/страница/scrollY переживают переход на страницу объекта и возврат назад. Восстановление скролла — через `onBeforeRouteLeave` (сохранить) + `onMounted` (`nextTick` + `requestAnimationFrame` дважды, чтобы дождаться реального рендера, затем `window.scrollTo`).
- `SITE_URL` (домен без `wp-json/`) экспортируется рядом с `API_BASE_URL` — нужен и для относительных URL в HTML-контенте (`../../` → абсолютный), и для ссылок в `wp-admin`.
- Заголовки WP иногда приходят с буквальными HTML entity-кодами (`&#8212;`) — раскрывать вручную через скрытый `<textarea>` (`decodeEntities`), сервер это не делает.
- Если у сущности нет своих таксономий (как у `attraction`) — не выдумывать фильтры на фронте, которых нет в данных.

### Каталог (`CatalogLayout.vue`)

- Слоты: `#heading`, `#description`, `#filters`, `#map`, `#grid`, `#pagination`. Общий для всех модулей компонент, его вёрстку под конкретный модуль не форкать — расширять через слоты.
- Переключатель «Карта/Каталог» + поиск — единый узнаваемый паттерн сайта: `FilterBar` (пунктирные пилюли-чипы, 1.5px dashed, ochre-заливка на активном) + `.search-box` (сплошная рамка 1.5px, радиус `var(--radius)`, ochre-обводка по фокусу, `min-height: 44px`) — см. `AttractionControls.vue`. Не изобретать новый стиль тумблера/инпута под очередной модуль.
- Если карте нужен весь набор данных сразу (кластеризация не работает постранично) — грузить всю коллекцию одним запросом, а каталожный вид фильтровать/пагинировать **на клиенте** поверх этого же массива, а не городить серверную пагинацию только ради второго режима просмотра.
- Bulk-эндпоинты часто отдают только маленькую WP-миниатюру (обычно 150×150) — той же самой, что используется для пинов карты. Для карточек шире ~300px она размывается. Решение — **не** тянуть оригинал целиком, а батч-запросом взять готовый средний размер: `GET /wp/v2/media?include=id1,id2,...&_fields=id,media_details`, выбрать `medium_large` → `large` → фолбэк на миниатюру (см. `useAttractionThumbnails`). Один запрос на видимую страницу каталога, не на каждую карточку отдельно.

### Карта (`AttractionMap.vue`, `vue-yandex-maps`)

- `initYmaps()` перед монтированием дочерних компонентов карты — у библиотеки бывает гонка при обычном автоинициализирующем монтировании.
- Кластеризация — `yandex-map-clusterer` с кастомной иконкой; кастомные маркеры — через `yandex-map-marker` со слотом.
- Кастомные контролы (`yandex-map-control-button`): обёртка библиотеки добавляет свой фиксированный паддинг (~8px с каждой стороны) поверх заданного размера вложенного контента — если нужен точный итоговый размер кнопки (как у соседних штатных контролов), считать размер вложенного `<span>` в обратную сторону (итог минус паддинг с двух сторон), а не выставлять размер самого контрола. Подсказка — своя всплывающая карточка в стиле проекта, не полагаться на нативный `title` (плохо стилизуется).
- Полноэкранный просмотр фото — всегда через переиспользуемый `ImageLightbox.vue` (зум, яркость/контраст, клавиатура, счётчик уже реализованы там). Не дублировать эту логику внутри очередного попапа/карусели — просто открывать `ImageLightbox` по клику на фото.
- Панель управления (переключатель + поиск) на карте — floating-плашка поверх карты в режиме карты, и та же панель обычной строкой над сеткой в режиме каталога (один компонент, два визуальных состояния через модификатор класса). Отступы от краёв — одинаковые в обоих режимах, чтобы при переключении режима элементы не «прыгали» по горизонтали.

### Страница объекта (`{Module}ItemView.vue` / `{Module}ObjectView.vue`)

Общая структура сверху вниз: breadcrumb → intro (фото + заголовок + место) → summary/content → галерея → навигация «Предыдущий/Следующий» → back-bar → похожие/ближайшие объекты.

- **Content-поле** — сырой HTML из WP. Относительные `../../wp-content/...` разворачивать в абсолютные через `SITE_URL` до любого дальнейшего парсинга.
- **Галерея из текста**: фото в `content` свёрстаны вручную (без единого стандарта), подписи — обычно следующей строкой под картинкой. Парсить через `DOMParser` (устойчивее регулярок к такой вёрстке), а не строковыми регэкспами — см. `extractGalleryAndCleanContent` в `useAttractions.js`. Вырезанные из текста блоки убирать из `content` целиком (иначе фото задублируется — один раз в тексте, второй в карусели), и подчищать опустевшие пустые обёртки-разделители (иначе их суммарный `margin` даёт заметный пустой хвост).
- Карусель для такой галереи — общий вид с попапом карты (рамка, счётчик, стрелки, миниатюры, клик → `ImageLightbox`), плюс подпись под фото — см. `AttractionGallery.vue`.
- **Навигация «Предыдущий/Следующий»**: `grid-template-columns: minmax(0, 1fr) minmax(0, 1fr)`, **не** просто `1fr 1fr` — иначе длинный несжимаемый заголовок раздувает свою колонку сетки шире положенных 50%. Заголовок — `overflow:hidden; text-overflow:ellipsis; white-space:nowrap`, плюс `:title="item.title"` для полного текста в нативной подсказке при обрезке. На ≤767px «Предыдущий»/«Следующий» сокращаются до «Пред.»/«След.» — двумя `<span>` с переключением `display` по брейкпоинту, без JS.
- **Back-bar**: основная CTA-кнопка (`.cta-btn`, ochre, bracket-clip-path) слева + неприметная ссылка «Редактировать» справа (`justify-content: space-between` на контейнере уже даёт нужное выравнивание). Ссылка — на `{SITE_URL}wp-admin/post.php?post={id}&action=edit`, `target="_blank"`, приглушённый цвет/opacity, не конкурирует по весу с основной кнопкой.
- **Похожие/ближайшие объекты** — сетка карточек `repeat(auto-fit, minmax(180px, 1fr))`, 1.5px dashed рамка, ховер: подъём + тень + ochre-рамка. Ранжирование — на сервере (см. ниже), не на клиенте.
- Ширина всех секций объектной страницы — унифицирована между модулями (`max-width: 1000px`), не подбирается заново под каждый модуль.

### REST-паттерны на бэкенде (`api/*/rest-api.php`)

- Bulk-эндпоинт списка — без пагинации, тяжёлые поля (`content`, аннотация) намеренно пустые в массовом ответе; подтягиваются отдельным запросом по id, когда пользователь открыл конкретный объект.
- `/{id}/adjacent` — предыдущий/следующий по возрастанию ID, опционально в рамках таксономии, если она есть у сущности.
- `/{id}/similar` (по совпадению таксономий/значимых слов) или `/{id}/nearby` (по гео-расстоянию, формула гаверсинуса) — ранжирование кандидатов **на сервере**, отдаётся top-4. Общая функция форматирования карточки для навигационных блоков (`format_xxx_nav_item`) переиспользуется между `/adjacent` и `/similar`|`/nearby`.
- Любые пороги/радиусы поиска (например, максимальная дистанция для «Объектов рядом») — обязательный параметр запроса с клиента, а не константа на сервере. На клиенте значение по умолчанию хранится в `window.__XXX__` в `index.html` (тот же принцип, что у `API_BASE_URL`/`YANDEX_MAPS_API_KEY`), не зашито в JS-бандле.
- `api/` в этом репозитории — рабочая копия исходников плагинов реального сервера (`testsite.vyatgeo.ru`), правки здесь применяются сразу. Проверять новый PHP через `php -l` (в системе есть несколько версий в `/c/OSPanel/modules/php/`, актуальный синтаксис — через PHP 8.x, не 7.4) и затем сверять живым запросом через `curl`.

## Правила работы

- Все цвета — через CSS-переменные (`var(--color-*)`), без хардкода. Отступы — через `var(--space-*)`.
- Типографика: Playfair Display (заголовки, вес 700) + Roboto Slab (весь остальной текст). Курсив/малые начертания Playfair — только для декоративных/цитатных случаев, не для обычного текста.
- Не использовать цветной `border-left`/`border-right` толще 1px как декоративный акцент на карточках/блоках — частый «AI-tell», сайт использует пунктирную 1.5px рамку как единственный декоративный приём.
- Отзывчивость: breakpoints 1023px и 767px. `min-height`/`min-width: 44px` на кнопках, чипах и интерактивных ссылках (WCAG touch target).
- Анимации — CSS transitions/transform, `prefers-reduced-motion` отключает их глобально (`base.css`).
- WCAG AA: контраст 4.5:1, `focus-visible` на всех интерактивных элементах (глобальный стиль уже есть в `base.css`, переопределять только при необходимости).
- После правок в `.vue`-файлах — прогонять детектор скилла `impeccable` и `npm run build`, прежде чем считать задачу завершённой.
