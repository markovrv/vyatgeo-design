# Плагин «Архитектура и скульптура г. Кирова: Прошлое и современность» (attraction)

Файлы: `api/attraction/` — `attraction.php`, `activation.php`, `register-attraction.php`, `rest-api.php`, `js/adminMap.js`, `templates/`, `vue/`.

## Назначение

Каталог архитектурных/скульптурных объектов Кирова с координатами для карты. В отличие от `artifact-finder`, плагин несёт собственный **скомпилированный Vue-бандл** (`vue/index.js` + `vue/index.css`, ~545 КБ, версия ассетов зашита в query-string `?1.4`), который монтируется на специально созданную при активации страницу `attraction-map` (`activation.php:2-12`).

## Зависимость

Требует активный плагин **Yamaps** (`yamaps/yamap.php`) — без него в админке показывается предупреждение (`activation.php:15-28`). Yamaps используется только в редакторе (карта выбора координат в метабоксе), не на фронтенде SPA.

## Регистрируемые сущности

- **CPT `attraction`** (`register-attraction.php:4`) — `show_in_rest: true`, `supports: title, editor, comments, revisions, thumbnail`, без собственных таксономий, архив включён.
- **Мета-поля** через `register_rest_field` (`register-attraction.php:32-51`, цикл по списку полей):
  - `attraction_coord` — строка координат `"lat, lng"`
  - `attraction_place` — текстовое описание расположения
  - `attraction_imgSrc` — URL картинки для маркера карты (если пусто — заполняется автоматически из featured image, `rest-api.php:35-40`, и сохраняется обратно в мета)
  - `attraction_color` — HEX-цвет маркера
  - `attraction_summarize` — аннотация объекта (textarea, отдельный метабокс)

Gutenberg отключён для `attraction` (`register-attraction.php:55-59`).

## Как рендерится фронтенд

`template_include` (`attraction.php:7-19`):
- одиночная запись (`is_single`) → серверный шаблон `templates/single-attraction.php`;
- страница `attraction-map` → подключается Vue-бандл как ES-модуль (`type: module`, `defer`, `crossorigin`) поверх шаблона `templates/template_for_yamap.php` — классическое Vue SPA, смонтированное в `<div>` на статической WP-странице.

## REST API

| Метод | Роут | Доступ | Назначение |
|---|---|---|---|
| GET | `/attraction/v1/objects` | публичный | Полный список объектов для карты, одним запросом |
| GET | `/attraction/v1/objects/{id}/adjacent` | публичный | Предыдущий/следующий объект по возрастанию ID (категорий у attraction нет — фильтровать не по чему) |
| GET | `/attraction/v1/objects/{id}/nearby?max_distance={km}` | публичный | До 4 ближайших по координатам объектов в радиусе `max_distance` км (формула гаверсинуса), отсортированы по расстоянию. `max_distance` обязателен — клиент хранит его константой (`window.__ATTRACTION_NEARBY_RADIUS_KM__` в `index.html`) и передаёт каждым запросом, на сервере не зашит |

Пагинации нет (`posts_per_page => -1` — забирает всё сразу, `rest-api.php:17`). Ответ — плоский массив (не обёрнут в объект):

```json
[
  {
    "id": 9655,
    "coordinates": [58.621791, 49.643526],
    "title": "Дача архиерея в Халкидоново со Свято-Духовской домовой церковью",
    "place": "ул. Лепсе, д. 14 г",
    "imgSrc": "https://.../wp-content/uploads/2024/11/....jpg",
    "color": "",
    "summarize": "",
    "content": "",
    "img": 9660
  }
]
```
Проверено на живом сервере — endpoint реально возвращает объекты.

**Важно**: поля `summarize` и `content` в ответе **намеренно всегда пустые строки** (`rest-api.php:54-55`) — это осознанное решение по производительности, а не баг. `/attraction/v1/objects` отдаёт все объекты одним запросом без пагинации (см. ниже), и включать туда объёмные `summarize`/`content` (HTML с картинками) для каждого из 400+ объектов раздуло бы этот массовый ответ. Эти поля объявлены в схеме, чтобы форма ответа была стабильной, но заполняются лениво — по требованию, отдельным запросом к `/wp/v2/attraction/{id}` (там `attraction_summarize` и `content.rendered` отдаются корректно благодаря `register_rest_field`), когда пользователь открывает конкретную карточку/объект.

Массив на выходе развёрнут в обратном порядке (`array_reverse`, `rest-api.php:62`) — новые объекты оказываются первыми.

`/adjacent` — `{ "prev": {...} | null, "next": {...} | null }`, каждый — `{ id, title, place, imgSrc }` (без координат/summarize — только на превью-ссылку).

`/nearby` — `{ "nearby": [ { id, title, place, imgSrc, distanceKm }, ... ] }`, до 4 штук, `distanceKm` округлён до 3 знаков.

## CORS

Явного заголовка нет, но WP-ядро отражает `Origin` так же, как и в остальных плагинах — проверено, работает.

## Замечания для интеграции

- Единственный источник данных для карты — `attraction/v1/objects`, целиком без пагинации; для 100+ объектов это разовый тяжёлый запрос, но зато без сложной постраничной логики на фронте.
- Для `ArchitectureObjectView.vue` (детальная карточка) — сначала список из `attraction/v1/objects` (координаты, заголовок, превью для карты/каталога), а `summarize`/`content` подтягивать по требованию отдельным запросом `GET /wp/v2/attraction/{id}` только при открытии конкретного объекта — так и задумано API, повторять эту же ленивую схему на фронте.
- Координаты хранятся как строка `"lat, lng"` в meta и разбираются через `explode(', ', ...)` — если в БД когда-то будет введён формат без пробела после запятой, парсинг всё равно сработает (разделитель жёсткий `", "`, но `explode` по любому совпадению строки, устойчив к отсутствию пробела не будет — стоит иметь в виду при вводе новых данных через админку).
